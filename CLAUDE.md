# The Moonsinger's Bell (my-manga): notes for Claude

A single-page browser game (Three.js r147, pixel-art sprites, voice-acted with Kokoro TTS), published by GitHub Pages from `main`:
https://taelkjfsdlkfje.github.io/my-manga/ . The owner tests on the live site, so **finished work is pushed straight to `main`** (they have asked for this every time). Commit and push only when they ask, or when the request says to push live.

## Where things are (read this before opening any file)

| Path | What it is |
|---|---|
| `index.html` (27 MB) | **Build output. Never read or edit it directly.** It contains the original game, the extension, and 25 MB of base64 voice clips. |
| `dev/ext/*.js` | **The source of every change since the original game.** They are concatenated in filename order into one `<script>` after the original game script. Edit these. |
| `dev/build.py` | Rebuilds `index.html` from the original game (git commit `6c09a24`, full id in build.py), small `patch()` edits to that original code, and `dev/ext/*.js`. It keeps the voice clips already in `index.html`. |
| `dev/game.js` | Generated by `build.py`: the original game script (with patches) and no voices, about 790 KB. **Use `grep -n` / `sed -n` on it to look at base-game code. Don't read it whole.** |
| `dev/build_voices.py` | Finds every voiced line in `index.html`, renders the missing ones with Kokoro, and embeds them. See `dev/docs/KOKORO_TTS_HANDOFF.md`. |
| `dev/harness*.js`, `dev/bot2.js`, `dev/t_*.js` | Headless Node test harness and bots (no browser). |
| `dev/assets/shayan/` | Shayan's sprite atlas, portrait strip, template and generator for `ext/02_shsprite.js`, plus the original 64px sheets. |
| `dev/docs/ARCHITECTURE.md` | Detailed map of systems, routes, fights, co-op and conventions. Read the section you need, not the whole file. |

## Setup (once per container)

`bash dev/setup.sh`. It runs `npm install` for the harness, which needs three@0.147. Voice rendering needs the Kokoro model files (~350 MB). Only set those up when there is new dialogue to voice; the steps are in `dev/docs/KOKORO_TTS_HANDOFF.md` §2 and §8.

## Build, test, release (run from `dev/`)

```bash
python3 build.py && node --check ext.js          # quick compile check (writes ext.js + game.js)
REAL=1 ROUTE=shayan CH=2 node t_full2.js ext.js  # full story route, prints ERRORS n (5-8 min)
REAL=1 node t_warp.js ext.js                     # every timeline warp reaches gameplay (~3 min)
python3 build.py --write                         # write ../index.html (keeps existing voice clips)
python3 build_voices.py ../index.html --dry-run  # lists dialogue that has no voice yet
python3 build_voices.py ../index.html --jobs 4   # render + embed (needs dev/tts/ models; ~4 lines/min)
```
Routes: `ROUTE=shayan|ali` with `CH=0` (Omar lives), `1` (Caotan lives) or `2` (both live / pact). Other tests are listed in ARCHITECTURE.md §Testing. Before pushing:
1. Run the routes your change touches, plus `t_warp`.
2. Check that both `<script>` blocks in `index.html` pass `node --check`. The release snippet is in ARCHITECTURE.md.

## Rules that save time and avoid bugs

- `.claude/settings.json` runs `dev/setup.sh` automatically at session start. It also blocks reading `index.html`, `dev/ext.js` and `dev/ext/02_shsprite.js`, which is mostly base64 image data; edit `dev/assets/shayan/sh_sprite_tpl.js` instead.
- When searching, exclude the huge files: `grep -rn PATTERN dev/ext dev/game.js --exclude=02_shsprite.js`. Never grep `index.html`: its VOICES line is 25 MB.

- **Never edit `index.html`.** Change `dev/ext/*.js`. Change base-game code only through `patch(s, old, new)` in `build.py` (the anchor must match exactly once).
- **Extension style:**
  - Wrap base functions by reassigning the global: `(function(){ const f=foo; foo=function(){ …; return f.apply(this,arguments); }; })();`.
  - Later files wrap earlier ones, so file order matters.
  - Function declarations are hoisted across the whole concatenated script; `const`/`let` are not.
- **Cutscenes are generators run with `run(gen)`.** They `yield say(who,text,ex)`, `choose([...])`, `wait(s)`, `tween(obj,props,dur)` or `cineTo(...)`. Fight patterns are generators that **yield plain numbers (seconds)**. Don't mix the two.
- **Voices:** a line is voiced only if `build_voices.py` can see a literal speaker and literal text, e.g. `say('caotan',"…")` or `twBark('omar',"…")`. `twBark(someVar,…)` is not voiced, so write `if/else` with literal speakers instead.
- **Read files in pieces:** `grep -n` first, then `sed -n 'a,bp'`. The base-game function names are listed in ARCHITECTURE.md §Base game.
- **Don't spawn subagents or use Playwright.** The owner asked for no Playwright. The Node harness covers logic; visual checks are for the owner on the live site.
- **`pkill -f`/`pgrep -f` patterns match their own shell command line.** Don't wait on a process with `until ! pgrep -f "build_voices.py"`; use a PID or a log file.
- The harness's `setTimeout` is a no-op and DOM objects are mocks. Code that must work in tests can't rely on timers or real images.

## The owner's preferences

- Tone: comedic, edgy, anime-cinematic, crude jokes are fine. Every boss has jokes, cut-ins, barks, and voiced lines.
- Mechanics: FF14-style telegraphs, parry-heavy combat (combos that stun when fully parried, plus easy single parries), reactive tells (glints).
- They want **no bugs that block completion**: test the routes and fights you touch with the harness.
- When they ask a question ("can you…?", "answer this and ask for approval"), answer and wait. When they ask for work, do it and push live.
- Final reports: start with the outcome, then list what to check on the live site. Keep it short.
- Secret keys in game: `Esc` opens the timeline (warps, save key); `0` god mode; `-` one-hit kill (only down to the next phase or limit cut); `9` unlocks all checkpoints; `P` pause; `V` voices; `M` mute.
